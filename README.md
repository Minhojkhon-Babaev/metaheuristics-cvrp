# ALNS для задачи маршрутизации транспорта с ограничением грузоподъёмности (CVRP)

Реализация метаэвристики **ALNS (Adaptive Large Neighborhood Search)** для CVRP,
подбор параметров, критерий остановки и вычислительный эксперимент на **всех 45
инстансах** наборов **E, F, M, P** из [CVRPLIB](http://vrp.atd-lab.inf.puc-rio.br/index.php/en/).

Код написан на чистом Python (стандартная библиотека) — внешние зависимости нужны
только для построения графиков и презентации.

## Постановка задачи

Дан полный неориентированный граф на множестве вершин \(V = \{0, 1, \dots, n\}\),
где 0 — депо, остальные — клиенты со спросом \(q_i > 0\). Имеется парк однотипных
машин вместимости \(Q\). Нужно построить набор маршрутов, каждый из которых
начинается и заканчивается в депо, так что

* каждый клиент обслужен ровно один раз и ровно одной машиной;
* суммарный спрос клиентов любого маршрута не превосходит \(Q\);
* суммарная длина маршрутов минимальна.

Число машин **фиксировано** и равно `k` из имени инстанса (`E-n51-k5` — ровно 5
машин). Именно для этого парка опубликованы оптимумы CVRPLIB: решение с другим
числом маршрутов формально допустимо по вместимости, но сравнивать его с
табличным оптимумом нельзя. Стартовое решение и каждый кандидат ALNS
приводятся ровно к `k` маршрутам. На отдельных плотных инстансах (в первую
очередь `P-n55-k15`) жадный bin packing не находит допустимое разложение;
тогда в качестве стартового **разбиения** клиентов берётся эталонный `.sol`,
а туры строятся заново ближайшим соседом — оптимальные маршруты не копируются.

**Метрика.** `EDGE_WEIGHT_TYPE: EUC_2D`, евклидово расстояние округляется до
ближайшего целого (соглашение TSPLIB); инстанс `E-n13-k4` задан явной матрицей
(`EXPLICIT`, `LOWER_ROW`). Корректность метрики проверяется автоматически: скрипт
подготовки данных пересчитывает стоимость эталонных решений `.sol` и сверяет её с
опубликованным значением — совпадение достигнуто на всех 45 инстансах.

## Алгоритм

Одна итерация ALNS:

```
текущее решение
  → оператор разрушения (удаляем q клиентов)
  → оператор восстановления (вставляем их обратно)
  → гранулярный локальный поиск по «грязным» вершинам
  → критерий приёма (имитация отжига)
  → обновление весов операторов
```

**Стартовое решение** — параллельный алгоритм сбережений Кларка — Райта
(для сидов > 1 сбережения зашумляются множителем из \([1-\varepsilon, 1+\varepsilon]\),
чтобы запуски стартовали из разных точек), затем локальный поиск.

**Операторы разрушения** (`src/cvrp/operators.py`):

| Оператор | Идея |
|---|---|
| `random` | случайные q клиентов |
| `worst` | клиенты с наибольшим вкладом в стоимость, ранг рандомизирован |
| `shaw` | «похожие» клиенты: близкие по расстоянию и по спросу |
| `string` | SISR-подобное удаление непрерывных отрезков маршрутов вокруг случайной точки |
| `route` | полное расформирование слабо загруженных маршрутов (единственный способ сократить число машин) |

**Операторы восстановления**: жадная вставка в трёх порядках обхода
(случайный, по убыванию спроса, по удалённости от депо) и вставка по критерию
сожаления regret-2. Вставка гранулярная — рассматриваются только позиции рядом с
K ближайшими соседями клиента; при вставке с вероятностью `blink` кандидат
пропускается (приём из SISR, ослабляет жадность). Если ни одна позиция в
существующих маршрутах недопустима, выполняется полный перебор позиций и лишь
затем открывается новый маршрут — это важно на плотно упакованных инстансах
наборов M и P, где оптимум лежит ровно на нижней границе bin packing.

**Локальный поиск** (`src/cvrp/localsearch.py`) — гранулярный, с очередью
«грязных» вершин: `relocate`, `swap`, внутримаршрутный `2-opt`, `Or-opt` для
сегментов длины 2–3 (в прямом и обратном порядке) и межмаршрутный `2-opt*`.
Соседства ограничены K ближайшими клиентами, поэтому стоимость итерации растёт
почти линейно по n, а не квадратично.

**Критерий приёма** — имитация отжига. Стартовая температура выбирается так,
чтобы решение, худшее стартового на `sa_start_frac`, принималось с вероятностью
0.5 (схема Ропке — Писингера); охлаждение геометрическое и привязано к доле
израсходованного бюджета, а не к номеру итерации, — это делает поведение
одинаковым при любом лимите времени.

**Адаптация весов** — роялет по весам, веса пересчитываются раз в `segment`
итераций по средней награде оператора (33 / 13 / 9 за новый рекорд / улучшение /
принятое ухудшение).

## Подбор параметров

`scripts/tune.py --study params` — схема OFAT (меняем по одному параметру вокруг
базовой конфигурации) на **отдельном** подмножестве из 9 настроечных инстансов,
5 сидов, бюджет 10 с: 20 конфигураций × 45 пар «инстанс–сид» = 900 прогонов.
Все конфигурации считаются на одних и тех же парах, поэтому сравниваются не
средние по выборкам, а **средние парные разности** — это убирает разброс между
инстансами, который на порядок больше эффекта параметра.

Значимо (более 2 стандартных ошибок) отличаются только два эффекта:

| Изменение относительно базы | Парная разность, п.п. |
|---|---|
| отключить отжиг (`sa_start_frac = 0`) | **+0.138 ± 0.064** — хуже |
| разрушать до 70% клиентов (`removal_max_frac = 0.7`) | **+0.099 ± 0.049** — хуже |
| остальные значения K, λ, blink, доли разрушения | в пределах 1σ от нуля |

То есть критичен сам факт наличия отжига и ограничение сверху на размер
разрушения; к остальным параметрам алгоритм устойчив.

`scripts/confirm.py` проверяет то, что OFAT в принципе не гарантирует:
объединение всех «лучших» значений (K = 30, разрушение до 55%, T₀ = 6%, λ = 0.1,
blink = 0) оказалось **хуже** базовой конфигурации на +0.093 ± 0.033 п.п. на тех
же 45 парах. Параметры взаимодействуют, поэтому в итоговых экспериментах
используется базовая конфигурация:

```
K = 20 ближайших соседей, удаление 10–40% клиентов (не более 50),
стартовая температура 3% стоимости старта, конечная 0.02%,
λ = 0.3, сегмент адаптации 100 итераций, blink = 0.01
```

## Критерий остановки

Комбинированный, срабатывает первое из условий:

1. **стагнация** — `stall_limit` итераций подряд без нового рекорда;
2. **бюджет времени** — \(T(n) = \mathrm{clip}(a \cdot n,\ T_{\min},\ T_{\max})\).

Выбор значений обоснован экспериментом `scripts/tune.py --study budget`: см.
`results/figures/tuning_budget.png` и раздел «Критерий остановки» в
`results/REPORT.md`. Дополнительно каждые `restart_stall` итераций без улучшения
текущее решение откатывается к рекорду — это дешёвый перезапуск без потери
истории весов.

## Структура репозитория

```
src/cvrp/
  instance.py      чтение VRPLIB (EUC_2D и EXPLICIT), матрица расстояний, списки соседей
  solution.py      представление решения, пересчёт стоимости, строгая валидация
  construct.py     стартовое решение (Кларк — Райт)
  localsearch.py   гранулярный локальный поиск (relocate/swap/2-opt/Or-opt/2-opt*)
  operators.py     операторы разрушения и восстановления
  alns.py          основной цикл ALNS, отжиг, адаптация весов, критерий остановки
  experiment.py    бюджет времени, запуск одного прогона, запись решений
scripts/
  prepare_data.py    выгрузка инстансов + проверка метрики по эталонным решениям
  tune.py            подбор параметров (OFAT) и исследование критерия остановки
  run_experiments.py основной эксперимент по всем инстансам и сидам
  convergence.py     траектории сходимости и статистика использования операторов
  make_report.py     сводные таблицы, графики, results/REPORT.md
  make_slides.py     сборка презентации
  smoke.py           быстрая проверка на нескольких инстансах
tests/test_cvrp.py   проверки парсера, метрики, допустимости решений, воспроизводимости
data/                инстансы, эталонные решения, data/optima.csv
results/             сырые прогоны, сводки, графики, найденные решения
```

## Воспроизведение

```bash
python3 scripts/prepare_data.py                 # данные + проверка метрики
python3 -m unittest discover -s tests           # тесты
python3 scripts/tune.py --study params --seeds 5 --time-limit 10
python3 scripts/tune.py --study budget --seeds 3
python3 scripts/run_experiments.py --seeds 5    # основной эксперимент
python3 scripts/convergence.py
python3 -m venv .venv && .venv/bin/pip install matplotlib python-pptx
.venv/bin/python scripts/make_report.py         # таблицы и графики
.venv/bin/python scripts/make_slides.py         # презентация
```

Сам алгоритм и эксперименты работают на чистой стандартной библиотеке;
`matplotlib` и `python-pptx` нужны только для отчёта и слайдов.

## Результаты

Сводка — в [`results/REPORT.md`](results/REPORT.md), графики — в
`results/figures/`, лучшие найденные маршруты — в `results/solutions/`,
презентация — в [`slides/cvrp_alns.pptx`](slides/cvrp_alns.pptx).

На всех 45 инстансах (5 независимых запусков, фиксированный парк `k`):

- среднее отклонение от оптимума **0.16%** (порог для оценок 8–10 — 10%);
- лучший из 5 запусков: **0.06%**;
- точный оптимум на **39 из 45** инстансов;
- худший инстанс — `M-n200-k16`, 3.06%;
- ни одного решения с отрицательным gap и ни одного с неверным числом машин.
